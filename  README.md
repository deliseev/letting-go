# Letting Go

Курс о том, как перестать писать на Go с ООП-акцентом.
Для разработчиков с опытом Python или C++.

> **Статус: черновик.** Содержимое неполное, структура меняется,
> ничего не зафиксировано. Репозиторий публичный по техническим
> причинам, а не потому что курс готов к чтению.

## О чём это

```go
type UserServiceInterface interface {
	GetByID(id int) (*User, error)
	Create(u *User) error
}

type AbstractUserService struct {
	repo RepositoryInterface
}

type UserServiceImpl struct {
	AbstractUserService
}

func NewUserServiceImpl(r RepositoryInterface) UserServiceInterface {
	return &UserServiceImpl{AbstractUserService{repo: r}}
}
```

Этот код компилируется, проходит `gofmt` и `go vet`. И это не Go —
это Java, записанная буквами Go.

Между «знаю синтаксис Go» и «пишу на Go идиоматично» лежит разрыв,
который не закрывается чтением документации. Tour of Go учит
синтаксису. Effective Go описывает идиомы — но для читателя, у
которого в голове нет конкурирующей модели. Проблема не в знании,
а в рефлексе: опыт в ООП срабатывает раньше, чем вы успеваете
принять решение.

Go этому не мешает. Компилятор придирчив к синтаксису и совершенно
равнодушен к архитектуре: двенадцать интерфейсов на одну
реализацию соберутся и поедут в прод. Обратная связь придёт через
полгода, когда связь между причиной и следствием уже не читается.

Курс — про то, как отпустить привычки, которые здесь стоят дорого.

Полная вводная статья: [`content/intro.md`](content/intro.md)

## Для кого

Предполагается, что вы прошли Tour of Go и прочитали Effective Go.
Синтаксис здесь не объясняется.

Не подойдёт, если вы пишете на Go первый месяц, ищете справочник
или готовитесь к собеседованию.

## Сборка

Сайт собирается [Hugo](https://gohugo.io/) с темой Hextra.

```
hugo server -D
```

Примеры кода лежат в `examples/` отдельными компилируемыми файлами
и включаются в текст по именованным регионам — правится код, не
листинг в markdown.

```
go test ./...
```
