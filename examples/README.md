# examples/

Компилируемые примеры кода, включаемые в `content/docs/` по
именованным регионам. Конвенция регионов — в `CLAUDE.md` в корне
репозитория.

## Включение в страницу

Шорткод `layouts/shortcodes/region.html` вырезает регион и рендерит
его через тот же партиал Hextra, что и обычные ` ```go ` блоки
(подсветка, кнопка copy, заголовок с именем файла):

```
{{< region file="foundations/value-receiver.go" name="value-receiver" >}}
```

`file` — путь относительно `examples/`. Ссылка на несуществующий
файл или регион валит сборку (`errorf`), а не рендерит пустой блок —
так `hugo` (и CI) ловит расхождение между текстом и кодом сразу, а
не молча публикует враньё.

## Линтер

`go test ./...` (через тесты в `lint_test.go`) проверяет каждый
`*.go` файл под `examples/`, кроме `*_test.go`:

- строка не длиннее 72 символов (`TestLineLength`);
- регион не длиннее 35 строк (`TestRegionSize`);
- у каждого `// region: X` есть ровно один `// endregion: X`, регионы
  не вложены и не дублируются в одном файле (`TestRegionStructure`);
- у каждого региона есть хотя бы один `{{< region >}}` в `content/`,
  который на него ссылается (`TestNoOrphanedRegions`) — файлы в
  `testdata/` из этой проверки исключены, они не курсовой контент.

Все четыре — реальные проверки текста файла и `content/`, а не
пересказ: ничего не гадает про длину строки или структуру регионов,
просто читает то, что есть на диске.

## Сломанные примеры

Некоторые модули намеренно показывают код, который не
компилируется, — в этом и есть антипаттерн. Такие файлы лежат под
build-тегом `broken`, поэтому никогда не попадают в обычный
`go build ./...` / `go test ./...`:

- Имя файла оканчивается на `_broken.go` и начинается с
  `//go:build broken`.
- Рядом лежит `<name>_broken.want` с точным `stderr`, который увидит
  читатель при компиляции этого файла, — не пересказ.

`go test ./...` (через `TestBrokenExamples` в `broken_test.go`)
собирает каждый `*_broken.go` с `-tags broken` и сравнивает его
stderr с `.want`. Ловит два вида поломки:

- Файл вдруг стал компилироваться — антипаттерн починили или новая
  версия Go начала его допускать. Нужно поправить пример или убрать
  его.
- stderr больше не совпадает с `.want` — обычно новая версия Go
  переформулировала диагностику. `.want` нужно обновить реальным
  выводом, а не подставить формулировку наугад.

`testdata/keyword_args_broken.go` — фикстура для проверки самого
механизма, не контент курса.

`go build`, `go vet` и `go test`, запущенные как `./...`, уважают
тег `broken` и пропускают такие файлы. `gofmt` — нет: он парсит
любой файл, на который его натравить, независимо от build-тегов, —
поэтому не гоняйте `gofmt` по `*_broken.go` напрямую: синтаксическая
ошибка там часто и есть смысл примера.
